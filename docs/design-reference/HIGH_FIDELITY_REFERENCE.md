# Catholic Knowledge — High-Fidelity Visual Reference

This document preserves the approved visual direction established in the product-design chat session and should be treated as a visual source of truth alongside `DESIGN_SYSTEM.md`.

## Product character

Catholic Knowledge should feel like a premium digital museum, illustrated encyclopedia, historical atlas, and visual knowledge explorer — not a generic SaaS dashboard or plain wiki.

Core palette:
- warm parchment / cream backgrounds
- deep Catholic navy for navigation, selected states, maps, and editorial feature cards
- restrained antique gold for halos, timelines, accents, and active states
- muted stone / parchment borders and secondary text

Typography:
- editorial serif display typography for major headings, quotations, entities, and historical storytelling
- clean sans-serif utility typography for controls and metadata
- strong hierarchy with spacious composition rather than dense enterprise UI

## Canonical home composition

The home experience should include:
1. A deep-navy knowledge-navigation rail with Catholic Knowledge seal/wordmark and semantic entry points.
2. A top navigation layer for Discover, Explore, Timeline, Learn, Ask, resources, locale, and search.
3. A large editorial hero combining:
   - Catholic Knowledge headline
   - tagline: Explore. Understand. Grow in Truth.
   - global search
   - popular knowledge chips
   - illustrated saint / historical visual treatment
   - quotation / story entry point
4. A prominent "Today in the Church" liturgical card.
5. An "Explore the Catholic World" semantic category strip.
6. A featured entity card with infographic metrics.
7. A visual knowledge-map teaser.
8. A Church History timeline teaser.
9. A guided learning-journey card.
10. Visual topic cards and a library/resource panel.

## Entity explorer

Entity pages such as St. Augustine should combine:
- illustrated portrait or editorial portrait slot with halo / architectural motif
- dates, roles, feast day, geography, and key metrics
- Overview / Timeline / Connections / Writings / Sources
- visual biography
- influence map
- doctrine/theme cards
- connected people, places, writings and ideas
- provenance clearly accessible

An entity is not just an article. It is simultaneously a biography, timeline, graph node, library entry, and learning surface.

## Knowledge graph

The graph follows the Archify interaction philosophy:
- graph is a central exploration canvas
- deterministic typed relationships
- semantic node styling
- knowledge lenses for People, Places, Writings, Events, and Doctrine/Ideas
- node search and highlight
- selected-node inspector
- upstream/downstream relationship exploration as the graph expands
- finite Story Mode motion
- source-aware nodes and edges
- synchronized timeline/story navigation where relevant

The graph must remain a factual deterministic visualization; generated raster imagery must never encode canonical factual relationships.

## Timeline

Church History should feel like a historical atlas:
- strong era/navigation treatment
- visual chronological spine
- major event cards
- connections from events into people, places, councils, documents, and doctrine
- ability to begin a guided story from a historical period

## Learning journeys

Journeys should feel more like an illustrated museum tour than an LMS:
- strong milestone navigation
- progress
- narrative canvas
- visual symbol / illustration per milestone
- related People / Events / Places / Sources
- transitions into graph and timeline surfaces

Flagship journey: **From Jesus to Nicaea**.

## Grounded Ask

Ask should remain secondary to exploration and evidence-first:
- elegant question entry
- explanation canvas
- visually distinct grounding/evidence panel
- entity, graph, timeline and journey actions
- citations/provenance visible

Product rule: **Sources create facts. AI creates explanations.**

## Visual storytelling rules

- Prefer diagrams, maps, timelines, iconography, visual relationships, and infographic facts over long walls of prose.
- Use Catholic architectural and manuscript-inspired motifs subtly, without kitsch.
- AI-generated imagery is editorial/atmospheric only.
- Canonical facts, diagrams, graph relationships, timelines and source references are data-driven and deterministic.
- Keep the experience beautiful on desktop while preserving clear mobile fallbacks.
- EN/VI is a first-class content and UI requirement.

## Broader page family

The design language should eventually cover:
- Discover
- Entity Explorer
- Knowledge Graph
- Church History Timeline
- Learning Journey
- Scripture Explorer
- Doctrine Visual Explainer
- Council Explorer
